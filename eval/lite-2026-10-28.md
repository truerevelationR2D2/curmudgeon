# Lite tier: short review files vs full-length (28 Oct 2026)

Question (03 §5.46): does asking the lite tier's one reviewer for short fields and a single write cut cost without
losing quality? Same targets, same model, 3 runs each, `/curmudgeon:review . (... use the lite tier)`.

| | 5.2 lite (full-length) | short lite (530c903) |
|---|---|---|
| Cost, 21 runs | $15.07 | $14.13 (-6%) |
| Median time per run | 239 s | 236 s |
| Suite 1 planted bugs | 45/48 | 44/48 |
| Suite 2 planted bugs | 70/81 | 65/81 |
| Suite 3 planted bugs | 5/6 | 6/6 |
| Suite 4 planted bugs | 12/12 | 12/12 |
| Impact misses | 1 | 0 |
| Clean twins: false alarms | 0 | 0 |
| Clean twins: BLOCK runs | 1 | 1 (a High on clean2 domain.js:11, labelled real in earlier runs) |

Recall per run on suite 2: 23, 25, 22 (full-length) vs 21, 22, 22 (short). Planted-bug recall needs no labels; the
unlabelled rows affect only precision.

With three runs per arm the suite-2 gap (5 of 81) sits inside the runs' own spread, so this is not proof that short reviews are worse; the release rule (§5.37) keeps a change only when no quality measure is worse, and here recall was lower on two suites, higher on one. The run folders are not in the repository (they hold full transcripts); the per-run numbers above are copied from `score.py` output.

Verdict: worse on planted-bug recall (127 vs 132 of 147) for a 6% saving, so under §5.37 and §5.45 the short-lite
change is removed and 5.2.1 keeps full-length reviews in every tier. Runs: scratch `evalruns/v52/lite52` and `lite521`.
