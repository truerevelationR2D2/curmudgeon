Tasks: suites 1–4 and the clean twins of suites 1 and 2, 2 runs each, 12 runs in all. Run folder: `eval/runs/2026-11-12-014855` (not committed; it holds transcripts).

**First attempt voided.** Run `2026-11-12-013116` stalled in every task: Curmudgeon prints its commands with the full path of the Python running it (since 5.3.1), and the arm allowed only `python3`, so 60 commands waited for an approval nobody gave. No tiebreaker was needed. All 45 were labelled real, including every finding on the clean twins (real bugs the clean copies still have). A scorer mismatch left repeat reports of a credited plant waiting for a label forever; that is fixed (25d8092, with a test that fails on the old scorer).

## Strict scorer (`score.py --gate`)

NOT MEASURED or FAIL, for reasons other than quality:
1. Cost is recorded in a different unit from the baseline (`--meta-cost` needed on both sides).
2. Findings with no label in `fp_labels.json`: the blind labels above live in the run's `labels.json`, which `score.py` doesn't read.
3. The clean twins FAIL the strict BLOCK floor: lite reported High findings on clean copy 1 (for example, a second tab's save silently deleting the first tab's notes). Both labellers judged them real. The floor passes a clean-twin finding only when it is labelled real in `fp_labels.json`.
4. "Answer-key leak" in suite2~2. This is a false match: the review wrote "status shown by colour dot only" for a real finding, the same 31 characters as answer-key entry E16 (the threshold is 30). The run's copy held no eval files. The leak check is unchanged.

## Reading

- Lite loses no precision: 111 of 111 findings were real, and there were no false alarms.
- Lite catches somewhat fewer planted bugs on the two large suites: suite 1 94% against 100%; suite 2 80% against 85–89%. Its single reviewer misses what a three-reviewer panel catches, and two runs are too few to separate this from noise (the two Suite 2 Wilson intervals overlap).
- Lite costs about half as much per run (median $0.69 against $1.54).
- The full tier is not re-measured on 5.6.0; the comparison is against a 5.4.x run and an older baseline.
